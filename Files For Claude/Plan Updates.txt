## SFZ Parser Fixes

### Fix 1 — `<control>` section skipped
- **Root cause:** all `<...>` headers triggered `flushRegion(); continue` — `<control>` was never entered
- **Fix:** added explicit `<control>` branch in `parseSFZ()`; `inControl = true`; reads `default_path=` from control section lines; `defaultPath` prepended to all `sample=` paths

### Fix 2 — `sfzOpcode()` truncated paths at first space
- **Root cause:** `Strings\Cello Section\susvib\` was being split at the space in "Cello Section"
- **Fix:** added `bool readToEOL` parameter to `sfzOpcode()`; `sample=` and `default_path=` opcodes use `readToEOL=true`

### Fix 3 — `key=` shorthand matching inside `lokey=` / `hikey=` ("only G notes play")
- **Root cause:** `line.indexOfIgnoreCase("key=")` matched at character offset 2 inside `"lokey=55"` and `"hikey=58"`, causing the `key=` shorthand handler to run on every `lokey=` and `hikey=` line — collapsing every multi-note zone to a single MIDI note (the hikey value)
- **Symptom:** only isolated notes across the instrument triggered sound instead of full key ranges
- **Fix:** word-boundary check added to `sfzOpcode()` in `VibePlayerDSP.cpp`:
```cpp
if (pos > 0 && (juce::CharacterFunctions::isLetterOrDigit (line[pos - 1])
                || line[pos - 1] == '_'))
    return {};
```
- Applied universally — prevents any opcode name from matching mid-word in any other opcode
