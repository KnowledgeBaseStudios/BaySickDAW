This layout is the quintessential heart of any DAW: the Piano Roll. Because this is highly interactive, standard UI buttons and sliders won't cut it for the main areas. Building this in JUCE for Vibesynth will require heavy use of custom components, custom `paint()` routines, and a lot of mouse listener logic.

Here is the topographical breakdown to feed to Claude, structured for your C++ JUCE architecture, keeping in mind how the bottom control section visually relates to your earlier Event Editor:

### **1. Top Toolbar (Tools & Context)**
This is a standard horizontal control strip managing the interaction modes for the piano roll.
* **Tool Icons Strip (Left):** A tight row of toggle buttons. Icons include: Wrench (options), Magnet (snap-to-grid), Pencil (draw), Paintbrush (paint multiple), Eraser, Mute (speaker with an X), Slice (razor), Select (lasso), Zoom (magnifying glass), and Playback (speaker).
* **Context Label:** Text dropdown/label reading `Piano roll - Sampler` (indicating which instrument is currently being edited).
* **Window Controls (Right):** Small utility icons (minimize, resize/maximize arrows).

### **2. Left Panel: Vertical Keyboard**
This acts as the Y-axis label for the main grid.
* **Main Area:** A vertical column component drawing a traditional piano keyboard.
* **Labels:** Text indicators on the "C" keys (e.g., C3, C4, C5) and an interactive state (keys should visually depress when clicked to audition the sound). *In JUCE, this is often implemented as a custom `juce::MidiKeyboardComponent` rotated vertically, or a completely custom painted class.*

### **3. Main Canvas: The Note Grid (X/Y Viewport)**
This is the primary interactive zone where MIDI notes are placed. It needs to be housed in a `juce::Viewport` to allow for scrolling.
* **Timeline Ruler (Top Edge):** A horizontal strip displaying measure/beat numbers (1, 2, 3, 4, 5).
* **Grid Background:** A dark 2D canvas with horizontal lines aligning perfectly with the piano keys on the left, and vertical lines indicating beat subdivisions.
* **Note Area:** *Ignoring the specific pre-placed notes per your request*, this area serves as a container for custom "Note Components" (which would be drawn as rounded green rectangles). These components need to support resizing (changing duration) and dragging (changing pitch/start time).
* **Scrollbars:** Standard vertical and horizontal scrollbars at the right and bottom edges.

### **4. Bottom Panel: Control / Velocity Editor**
This pane manages per-note data (like velocity, panning, or pitch bend). Visually, it borrows concepts from the Event Editor you showed me earlier, but applies them to discrete events rather than a continuous automation line.
* **Header / Target:** A dropdown menu reading `Control > Velocity`. 
* **The Graph Area:** A grid background matching the exact vertical lines/timing of the Main Canvas above.
* **Event Display Style:** Instead of a continuous line (like the volume automation in your Event Editor), this displays data as **vertical stalks** corresponding to the exact horizontal start-position of a note in the grid above. 
    * Each stalk has a draggable node (a small circle) at the top.
    * A horizontal line extends to the right from the node, representing the duration of the note.
    * Dragging the node up or down changes the velocity value for that specific note.
* **Divider:** A horizontal draggable separator sits between the Main Canvas and this Bottom Panel, allowing the user to resize the height of the Control Editor.
