Context
Jeff wants to evolve VibeDAW from a focused music-starter tool into a feature-complete DAW rivaling FL Studio in workflow. The v2.0 documentation spans 28 files covering a complete overhaul of the UI shell, two new sound engines (Harmless additive synth + VibePlayer disk sampler), a professional-grade Mixer page, a full Playlist/Builder page, an Event Editor, a standardized effects rack, and an NSIS installer with sample download.
Core philosophy of this plan: Preserve every working component in the current build, build new systems alongside them, then wire them together phase by phase. Nothing is torn out before its replacement is proven.

Architectural Decisions
1. AudioProcessorGraph replaces direct buffer mixing
The current processBlock manually creates and sums layersBuf, bassBuf, drumsBuf. Phase 5 replaces this with a juce::AudioProcessorGraph that models:

Master Node (output)
Layers Buss → Master
Bass Buss → Master
Drums Buss → Master
Per-instrument nodes → respective Buss
Each instrument node hosts its 6-slot FX rack

2. JUCE UndoManager — introduced in Phase 1, used everywhere
A single juce::UndoManager instance is owned by StandaloneEditor and passed by reference to all subsystems. The existing PianoRoll local undo stack is migrated to use it in Phase 6.
3. Ribbon tab system replaces fixed 5-tab layout
StandaloneEditor currently hard-codes 5 pages. Phase 1 introduces RibbonTabBar (custom juce::Component). System tabs (Mixer, Effects, Builder) are permanent and non-closeable. User-added tabs (Layers, Bass, Drums) are dynamic.
4. Page content model
Each page is an independent juce::Component that owns a track ID into the AudioProcessorGraph. A page's 3 sub-tabs (Sound / Piano Roll / EQ) are created lazily after the user selects an engine from the dropdown.

Phase 3 — Core Sound Generators
Goal: Build Harmless and VibePlayer as independent audio engines. Do NOT hook into the UI yet.
3A — Harmless (Additive Synth Engine)
Architecture: IFFT-block rendering (most efficient for 516 partials)
Classes:

HarmonicEngine — owns 516-partial arrays (freq, amp, phase as std::array<float, 516>); all pre-allocated in prepareToPlay; IFFT rendering block via juce::dsp::FFT inverse
SpectralModule (base) → PrismModule, PluckModule, BlurModule, FilterMaskModule, PhaserMaskModule
AdditiveVoice : juce::SynthesiserVoice — owns HarmonicEngine + two Part A/B instances
HarmolessSynth : juce::Synthesiser — manages up to 16 AdditiveVoice instances
HarmlessProcessor — thin wrapper (NOT a plugin, just a juce::AudioProcessor subclass for editor hosting)
HarmlessEditor : juce::AudioProcessorEditor — full UI with spectrogram (lock-free FIFO → GUI), spline envelope editors, modular unit order drag-and-drop

Key DSP rules:

Zero allocations on audio thread
juce::SmoothedValue for all parameter transitions
SIMD via juce::dsp::SIMDRegister in partial summing loop
Sine LUT (4096 samples) replaces std::sin
Partial culling: skip if freq > Nyquist or amp < -80dB

Files: Source/Harmless/ folder (new): HarmonicEngine.h/.cpp, SpectralModules.h/.cpp, AdditiveVoice.h/.cpp, HarmolessSynth.h/.cpp, HarmlessProcessor.h/.cpp, HarmlessEditor.h/.cpp
3B — VibePlayer (Disk Streaming Sampler)
Classes:

VibeRegion — maps {rootNote, loNote, hiNote, loVel, hiVel, roundRobinIndex, articulationGroup} to audio file
VibeSampleManager — recursive folder scanner (C3_v127_RR1.wav filename parsing) + SFZ parser; populates std::vector<VibeRegion>
VibeVoice : juce::SynthesiserVoice — per-voice: juce::ADSR, juce::dsp::StateVariableTPTFilter (muffle + treble), juce::dsp::WaveShaper (overdrive), juce::BufferingAudioReader for disk streaming
VibeSynth : juce::Synthesiser — overrides noteOn for articulation group selection (key-switch / velocity-threshold / CC)
VibePlayerProcessor — thin wrapper
VibePlayerEditor — UI: instrument selector, knob panel (Decay, Release, Pan/Tremolo, Stereo, Overdrive, LFO, Treble, Stretch, Muffle, Hardness, Sensitivity, Tune, Detune)

808/909 Bass special case: BassVibeSynth : VibeSynth — VibeSampleManager points to in-memory PCM from existing BassSynth; no disk streaming needed; same VibePlayer UI knobs
Files: Source/VibePlayer/ folder (new): VibeRegion.h, VibeSampleManager.h/.cpp, VibeVoice.h/.cpp, VibeSynth.h/.cpp, VibePlayerProcessor.h/.cpp, VibePlayerEditor.h/.cpp, BassVibeSynth.h/.cpp

Phase 5 — Global Routing & Mixing (AudioProcessorGraph)
Goal: Replace direct buffer mixing with a proper graph. Build the Mixer page.
5A — AudioProcessorGraph Architecture
Replace processBlock direct mixing with:
GraphNode[0] = MasterOutputNode (→ hardware out)
GraphNode[1] = LayersBussNode (compressor/level) → MasterNode
GraphNode[2] = BassBussNode → MasterNode
GraphNode[3] = DrumsBussNode → MasterNode
GraphNode[4+] = InstrumentNodes (one per active page tab) → respective BussNode

InstrumentNode wraps: engine processor (HarmlessProcessor / VibePlayerProcessor / DrumSynthProcessor) + per-track EffectRack (6 slots)
Dynamic allocation: when a tab is added, a new node is inserted; when closed, node is removed
Channel ordering per spec: Layers group → Bass group → Drums group (with spacers)
Cycle detection: prevent feedback routing loops
PDC: calculate across graph when nodes are added/removed/latency changes
Files: Source/VibeGraph.h/.cpp (new); update PluginProcessor.h/.cpp

Consistency Review — Cross-Phase Gaps & Missing Components
After reviewing all 6 phases as a unified system, the following are not covered in the provided documents and must be addressed before building begins or during implementation:
Critical Missing Items

MIDI Input/Output device configuration

The Options > Audio Settings references device setup, but no MIDI device selection is documented. The Global Transport plays patterns but never shows how external MIDI controllers send notes to instrument pages. Decision needed: does v2.0 support live MIDI input, and if so, which device picker is used?


Hardware Audio Device Setup (ASIO)

Options > Audio Settings is in the menu but no ASIO/CoreAudio device configuration panel is documented. The StandaloneApp must configure the device. Does Jeff want a full ASIO dialog (juce::AudioDeviceSelectorComponent) or the existing basic setup?


Plugin Hosting (VST/AU third-party effects)

The Mixer spec references VST/AU plugins in FX slots (right-click → Plugin Picker, Browser plugin database, etc.). Building a full VST/AU host is a major separate effort. Recommendation: Phase 5 ships with internal effects only; VST/AU hosting deferred to v2.1.


Browser Panel

Mixer, Builder, and Event Editor all reference "Browser > Current project > ..." with folder trees for patterns, parameters, effects. No Browser document exists. Likely needed in Phase 6 for Automation Clip workflows. Recommendation: Build a minimal read-only project browser in Phase 6 that shows patterns and their automation targets.


Undo History Window

Referenced in EDIT menu. Simple juce::ListBox backed by UndoManager transaction names. Low complexity but must be built in Phase 6A.


Time Signature Support

Builder page allows per-bar time signature changes, but PatternManager only stores BPM. The StandalonePlayHead needs to deliver time signature info. Must be added to PatternData in Phase 6.


Audio Recording

Mixer track arming (red button) is fully specced but there's no audio recording engine. Recording requires juce::AudioDeviceManager audio input, a write-to-disk thread, and Audio Clip creation. Recommendation: Stub the arm button in Phase 5; full recording deferred to v2.1.


Sample library URLs are Mega.nz folder links

The Sample Download Architecture document lists Mega.nz folder links (https://mega.nz/folder/...) which cannot be downloaded directly via HTTPS — they require the Mega SDK or a browser session. The NSIS installer will need MEGAcmd or an alternative hosting URL (AWS S3 / Dropbox direct link). Jeff must re-host the sample ZIPs on a standard HTTPS direct-download URL before the installer can be built.


Project Auto-Save / Crash Recovery

Not documented but critical for a DAW. Add to Phase 7A scope.


Font & Asset Bundling

New UI (Chrome tabs, menu bar, effects page) will need consistent fonts. Ensure all fonts are embedded in the binary via BinaryData or JUCE font loading.



Lower-Priority Items (Defer to v2.1)

Multi-touch support (Mixer + Builder gesture modes)
Surround sound (5.1 / 7.1) output routing
Audio stretching / time-warp (Slip Edit on Audio Clips)
Stem extraction (ML-based, referenced in Builder clip menu)
Performance Mode full implementation (can be stubbed in Phase 6)
Patcher/FX graph-within-a-slot (referenced in Mixer FX slot menu)
