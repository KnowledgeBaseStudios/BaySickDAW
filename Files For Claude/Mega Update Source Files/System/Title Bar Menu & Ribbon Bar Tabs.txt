Part 1: Title Bar Menu Structure
The main menu bar will be implemented with standard JUCE menu objects (e.g., juce::MenuBarComponent and juce::PopupMenu) and will contain the following top-level options: FILE, EDIT, PATTERNS, VIEW, OPTIONS, and HELP.
1. FILE Menu
* New: Starts a new, empty project using the last selected template as a start point. You will be prompted to save any changes made to the current project.
* New from preset: Starts a project by selecting a preset from a drop-down, with the default being the first and preselected option. To set the default preset when opening new projects, use the General Settings option in the Options Menu.
* Open (Ctrl+O): Opens an existing project.
* Save (Ctrl+S): Updates the project by overwriting the last saved copy on disk.
* Save as (Shift+Ctrl+S): Saves the current project under a different name.
* Save as preset: Saves the current project to the preset folder.
* Export: Pulls up a window with options to convert the current project to various file formats. By default, the Master Mixer track is rendered, unless you are using 'Split mixer tracks'. If using 'Split mixer tracks', the export will render files in the selected format for each track that isn t muted in the mixer on the builder page tab.
o Audio Formats: .wav and .mp3 formats save an audio mix of your project.
o Render length: The total length depends on the selected mode:
* 'Song mode' hierarchy: 1. Any time-line selection on the builder page tab. 2. The last time-marker beyond the last bar containing data. 3. The end of the last bar containing data. 4. The Tail setting, allowing the tail of the sound to continue until dbfs is at -60.
* 'Pattern mode' hierarchy: 1. The last time-marker beyond the last bar containing data in the Pattern. 2. The end of the last bar containing data in the Pattern. 3. The Tail setting.
o Export Window - WAV (Wave): Lossless uncompressed audio, preferred for production environments to save samples, sounds, and archive material. Contains a drop-down menu for bit-depth options, which affects the noise-floor (the quietest sound captured or smallest changes in loudness resolved). Generally, 16-bit is enough for distribution, while 24 or 32-bit is for archiving.
* 16-Bit integer wave: The highest-quality audio file compatible with a wide range of playback devices and the CD audio format. Note: VibeDAW does not burn to CD; it creates files ready for burning using any VST CD burning program. Ensure 44.1 kHz is set in Audio Settings for CD compatibility.
* 24-Bit integer wave: A common bit-depth used by DAW hardware and older DAW software. Use if 32-bit float is not supported by the device or application.
* 32-Bit floating point: The native format of VibeDAW s mix engine. Render to this format for continued mixing or editing in another application supporting 32-bit float. It provides more precision for audio processing, ensuring highest quality during post-production.
o Export Window - Sample rate: VibeDAW uses 44100 Hz (44.1 kHz), as it is the CD standard and captures the entire human hearing frequency range (20 Hz to 20 kHz).
o Export Window - Channels: Refers to 'stereo' channels, not 'Instrument Channels'.
* Stereo: Two channels for the Left and Right speakers.
* Mono (merged): One channel where the left and right channels are merged into a single channel.
o Export Window - MP3/OGG/M4A: Lossy compressed audio formats that compact audio to save space. Lower bit-rate settings may cause unwanted artifacts described as 'underwater sounds' or 'bubbling'. A slider sets the bit-rate; higher bit-rate improves quality but increases file size. The maximum bit-rate for MP3 is 320 kbps. Check rendered files with headphones prior to release. Where possible, use at least 16-Bit .wav when sharing or saving in a production environment.
* 128 kb/s: Point of 'acceptable' quality for most; useful for emailing.
* 160 kb/s: Difficult for many to distinguish from CD; a good minimum for distribution and listening. Listen carefully with headphones as some material may still produce artifacts.
* 224 kb/s (or greater): Practically indistinguishable from CD under normal conditions. A good minimum for archiving a quality compressed copy. Useful for internet collaboration when 1400 kb/s CD .wav format is impractical.
2. EDIT Menu
* Undo (Ctrl+Z).
* Redo (Ctrl+Alt+Z).
* History: Opens a window with undo/redo history.
* New Layers page tab.
* New Bass page tab.
* New Drums page tab.
3. PATTERNS Menu
* Find next empty (F4): Finds the next unused pattern in the list (a good workflow habit).
* Select in builder page tab: Selects all instances of a selected pattern on the Builder page tab.
* Rename and color (F2): Opens the Pattern naming window. Press F2 again to cycle colors, or click the Pattern colors button in the naming window.
* Insert one (Shift+Ctrl+Ins): Inserts a new empty Pattern before the selected pattern.
* Clone (Alt+C): Makes a copy of the selected pattern directly after it.
* Delete (Del): Deletes the selected pattern.
* Move up (Shift+Ctrl+Up arrow): Moves the selected pattern up one number in the Pattern selector list.
* Move down (Shift+Ctrl+Down): Moves the selected pattern down one number in the Pattern selector list.
* Split by channel: Creates a new pattern for each active Channel (based on active audio going to mixer channels) within the selected pattern. Patterns will be named according to the split Channel.
4. VIEW Menu
(Contains commands for changing between VibeDAW page tabs)
* Layers (F5): Goes to the most recent Layers page tab.
* Bass (F6): Goes to the most recent Bass page tab.
* Drums (F7): Goes to the most recent Drums page tab.
* Builder (F8): Goes to the Builder page tab.
5. OPTIONS Menu
(Contains commands that set VibeDAW options)
* General settings: Shows/hides the General Settings window allowing you to select which preset is default.
* File settings: Shows/hides the File Settings window allowing you to select which local folder is the project default.
* Audio settings: Shows/hides the Audio Settings window allowing you to select which driver you are using.
6. HELP Menu
(Contains commands for access to the reference system and documents)
* Help Index (F1): Opens the VibeDAW manual.

Part 2: Ribbon Bar Tabs Setup (JUCE Architecture)
This section outlines the strict requirements for writing the complete header (.h) and implementation (.cpp) files for a Chrome-style tabbed interface in JUCE.
1. Hard-Coded System Tabs
* There must be three permanent tabs that appear across all projects in every instance, with no exceptions: Mixer Page Tab, Effects Page Tab, and Builder Page Tab.
* These must always remain in this exact order and must not have an 'x' button to close.
2. Custom Component Architecture & Overflow Logic
* Encapsulation: Create a custom juce::Component that encapsulates both the tab headers and the main content area.
* Minimum Tab Width: You must explicitly enforce that tabs never shrink below a readable minimum width (e.g., 100 pixels).
* Avoid Default JUCE Behaviors: Do not rely on JUCE's standard TabbedComponent overflow (left/right scroll arrows) or standard setOutlineThickness().
* The resized() Implementation: The AI must explicitly calculate how many tabs fit in the current width. Look for explicit logic in the resized() function that checks getWidth() against (numTabs * minTabWidth).
* Overflow Menu Trigger: If there are more tabs than available space, instantiate a small overflow button (e.g., ">>" or a chevron icon) next to the "+" button.
* juce::PopupMenu Integration: Clicking the overflow button must trigger a juce::PopupMenu listing the names of all currently hidden tabs. Selecting an item from this popup must bring that specific tab into focus and swap it into the visible tab bar.
3. Visual & Interactive Elements
* Chrome Aesthetics: Implement basic drawing in paint() or paintButton() for a modern, Chrome-like appearance. This includes slightly rounded top corners, distinct active versus inactive backgrounds, and no visible border between the active tab and the content area.
* The Add Tab (+) Button: A static '+' button must be located immediately to the right of the last visible tab (or next to the overflow button if the overflow is active). Clicking it dynamically generates a new tab with the options being Layers Page, Bass Page, Drums Page.
* Tab Closure: Every user-generated tab must include a small 'x' button on the right side to safely close and delete it (excluding the three hard-coded system tabs).
* Double-Click to Rename: The text on each tab must be editable. Create a custom button class utilizing a juce::Label configured with setEditable(false, true, false) so that a double-click makes it editable. Include a listener to update the internal name of the tab when the user finishes typing.
* Hover Tooltips: Every tab must display a tooltip containing its full, current name upon hover. Ensure the custom tab button implements juce::SettableTooltipClient or overrides the getTooltip() method.
